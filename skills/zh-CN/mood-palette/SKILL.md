# Mood Palette

按情绪选择三色组合，再分配颜色角色与面积。保留用户已有的主体、布局和品牌约束。

## 怎么调用

使用 `$mood-palette` 加自然语言任务，例如：

- `$mood-palette 推荐适合茶品牌的配色，只给色值和用途。`
- `我想要一组以蓝色为主题的配色，推荐 5 个组合供我选择。`
- `$mood-palette 用奶油晴空生成一张静物插画，横版，无文字。`
- `$mood-palette 用 moss-tea-05 给当前页面改色，保留布局和交互。`

只询问用法或只写 Skill 名时，展示常用句式；不默认开始生图或改文件。更多可复制例子见 [调用示例](references/usage.md)，在用户问用法或需要批量约定时读取。

按用户要的交付物处理：

| 请求 | 交付 |
|---|---|
| 看配色、推荐或对比 | 直接展示库内对应配色图片，附普通色名、建议主色与简短理由 |
| 生成插画、海报、包装图或 UI 示意图 | 实际调用可用生图工具，交付图片与提示词；有 imagegen 时使用它 |
| 只要提示词 | 可复制提示词；不开始生成图片 |
| UI 配色变量 | 沿用项目命名输出 CSS/项目原有格式的语义变量，附实测对比度 |
| 给现有页面改色 | 修改配色与语义变量，保留布局、内容和业务交互，并检查实际页面 |
| 检查配色或对比度 | 报告测量值与问题；只有要求修复时才改色 |
| 批量示例或同色对照 | 先明确用途、色组与数量对应关系，再逐项生成和核对 |

用途、氛围、主题/编号、尺寸和交付格式都是可选输入；从当前任务补全。用户给出足够信息时直接执行。品牌约束与用户指定色组优先，额外的设计 Skill 负责布局、字体或组件，本 Skill 提供颜色关系与语义映射。

## 选择色组

用户不必知道主题名。“蓝色为主”“浅一点的粉红色”“明亮、低饱和”等描述优先走 [日常颜色检索](references/search.md)，把语言归一为基本色、明暗和饱和度条件，调用脚本取得真实候选；不要只按主题名称猜测。未给数量时默认推荐 5 组。明确数量时按要求返回，不够时说明实际数量，不拼造新组补足。

推荐时直接展示数据 `image` 字段对应的预渲染三栏色卡（相对于 Skill 目录），每组一张。色卡仅由库内 HEX 绘制，包含等宽纯色色块、HEX 与编号，不使用参考原图或其裁片；推荐时直接复用色卡，不另画检索图或调用生图工具。支持图片的聊天中嵌入图片；本地图片使用解析后的绝对路径。无法内嵌时附可打开的图片文件，不能只交付颜色名字或编号。图片下附“蓝灰＋深蓝＋浅灰”等普通描述、建议主色与一行区别，编号和可复制 HEX 作补充。只要色值时才仅返回文字。原主题名作为补充。用相同三色换序或近似重复不算不同候选。蓝色主题表示推荐将蓝色用于主色；原数据没有面积比例，使用比例由应用决定。

用户要求“供我选择”或只要推荐时，交付候选后等待选择，不开始生图或改页面。“第 3 组”对应上一轮实际展示的编号；后续生成沿用该编号，避免重新排序后换组。用户同时指定“推荐并直接用一组生成”时，选定并报告编号后继续执行。

先读 [配色索引](references/index.md)，按主题从 [色值数据](references/palettes.json) 选择一组完整三色及其配色图片。用户指定编号时直接使用该组；只指定主题时按用途从该主题选择所需数量的编号并报告；指定编号不存在时说明并给邻近候选，不静默替换。信息充足时直接选定并简述原因。

也可用标准库脚本精确取数，路径均相对此 Skill 目录：

```bash
python3 scripts/palette.py --list
python3 scripts/palette.py moss-tea-01
python3 scripts/palette.py --search 蓝色 --limit 5
python3 scripts/palette.py --search 粉红色 --lightness light --saturation muted --limit 5
```

使用编号、三色 HEX 和颜色角色说明本次选色。记录顺序不表示主辅色或面积比例。不同组的颜色不自动混合；确需跨组时说明是新组合。

数据包含 12 个主题、100 组组合。`printed_hex` 为标签转录值；`image_sample` 为参考图采样的近似值。取值方法见 [准确性说明](references/accuracy.md)。新增、调亮、压暗的颜色标注“应用派生”，保持原记录可追溯。

## 用于生图

将选定三色分别写成“可理解的色名 + HEX + 用在哪里”，例如背景、主体、光线或小物。按照画面意图分配面积；无明确要求可从 60/30/10 开始，这是应用建议。强调最重要的色彩关系：冷暖、明暗、饱和度与点睛位置。

将这些信息融入现有生图工具的提示词，按用户要求实际生成图像。只要提示词时交付可复制提示词即可。使用已有可用的图像生成工具，保持主体和构图要求；无需给本 Skill 绑定特定服务。

示例（`cream-sky-01`，此处色名为解释）：奶油白 `#FCF5D2` 的留白背景约 60%，浅天蓝 `#C0E3F5` 的主体约 30%，柔黄 `#FFEC8E` 的光点或小物约 10%；明亮、轻盈、低反差。避免把三种颜色平均涂满画面。HEX 是意图约束，生成图的像素色值需要另行取样才能验证。

## 用于 UI

将三色映射到项目已有的语义变量；需要新增时至少明确 background、surface、text、muted-text、primary、on-primary、accent、border、focus 的实际用途。原三色不够时补充同色相的深浅层级或中性色，逐个注明“应用派生”。情绪色不直接等同于成功、警告或错误语义；沿用项目已有状态规则。

对实际使用的文字/背景、按钮文字/按钮填充、必要控件边界/相邻背景计算对比度。正文至少 4.5:1；大字（24px 常规或约 18.67px 粗体）至少 3:1；传递识别信息的控件边界和图形至少 3:1。参见 [W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 与 [非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

```bash
python3 scripts/palette.py --contrast '#252A24' '#FCF5D2'
```

只报告实际算出的对比度，纯检查不自动改变颜色；只有已要求选色、应用或修复时才派生新色并重算。脚本计算不透明 sRGB 实色。透明、渐变、图片背景先取得合成后的实际颜色；对比度不通过就调整用途或派生颜色后重算。浅色三色组通常适合作背景/表面/装饰，需要额外深色正文；不能因为配色柔和就使用浅灰正文。hover、pressed、focus 等状态也检查实际配对。交付 UI 时提供颜色变量和关键配对的验证结果，并以页面渲染核对应用效果。

## 批量与复用

将任务记成“用途 × 色组 × 张数”的清单；“共 10 张”是总量，“各 10 张”按用途分别计数。默认分配时简述分配并执行，只有数量含义实质不清才询问。图像示例逐张调用生图工具，一张拼图不计为多张独立交付。保存每张原图、配色编号、用途和提示词，按清单核对完成项并提供图集；失败项说明原因，工具不可用时不把提示词冒充成图。

“同一配色跨用途”沿用同一编号的原三色，允许为文字、材质与光影派生层级并标注。“继续用这组”从当前任务的已选编号和变量继续；跨页面复用沿用项目现有 token 文件或 DESIGN.md，用户要求持久保存时更新对应文件，省去额外的平行配置。

## 交付与扩充

随作品简短说明：使用的编号与情绪、三色与角色、是否有应用派生。近似值首次说明即可。用户只要成品时不附长篇配色分析。

用户提供新参考图或截图时，先核对色组关系，再写入数据：可读 HEX 原样抄录；采样记为 `image_sample`；自行构想的色组标注“新配色”，与采样记录区分。对外数据仅保留用途所需的编号、主题、三色、图片相对路径与取值方法。对外图片仅从最终 HEX 重新渲染，参考整图或裁片不进入 Skill 资产。需保存的取色位置和参考说明放在私有工作记录中，不随公开包分发；公开文件省略平台名、账号、主页链接和个人信息。使用明确增量更新，不把旧组替换成新猜测。
