# 手机底图与壁纸

当用户上传底图、要求保留照片内容改色，或准备手机壁纸时读取。名称始终为 Mood Palette，Skill 标识与桌面调用名始终为 `mood-palette` / `$mood-palette`。手机 ChatGPT 通过宿主的 `@` 菜单选择插件；用户输入 `$mood-palette` 时也按本流程理解，不给用户改名。

## 输入与选择

用户直接在当前聊天从手机相册上传照片即可。使用当前附件，不要求先传电脑、本机路径或另一个网盘。没有附件却要求编辑底图时，请用户在当前聊天附图；可以先推荐配色，但不把文字生图当作编辑其照片。多张图用途不明确时，先确认哪张是底图、哪张仅供风格参考。

- 底图是编辑目标：保留主体身份、物体数量、姿态、构图及用户指定的重要细节。
- 三栏色卡只提供颜色：色块、HEX、编号、文字和边框不进入成品。
- 用户要求“只推荐”“先选色”时，展示默认 5 张库内干净色卡后停下，等待选择。
- 用户已经选定编号，或明确要“挑一组直接做”时，报告所用编号后继续编辑，不再要求多一次确认。

检索时，有 Python 环境就运行现有脚本；没有时读取 [免运行索引](portable-search.json)。键为 `基本色|明暗或any|饱和度或any`，例如 `blue|any|any`、`pink|light|muted`。基本色使用 blue/pink/yellow/red/orange/green/cyan/purple/brown/white/gray/black/any；从当前语言归一到这些键。每个条件的数组已经排序并去重，取前 N 项（默认 5），再从 [色值数据](palettes.json) 按 ID 读取原三色和图片路径。数组为空或不足时报告实际数量，不补造或静默放宽条件。按氛围选色时参考 [主题索引](index.md)，也只使用库内编号。

色卡路径相对于宿主加载的 Skill 资源目录。使用宿主提供的实际文件、附件或资源地址展示原有 PNG；本地执行时才解析为本机绝对路径。不要把电脑目录当手机可访问链接，不猜测 CDN 地址，也不要求重新下载早期参考图。若宿主不能展示或交付资源文件，明确报告图片展示受限，附真实色值作为临时补充，不宣称已展示色卡。

将本轮序号、实际编号、建议主色和所用底图关联保留在当前对话中。后续“第 2 组”“继续用这张图”沿用这个对应关系；不重新检索后换掉序号。

## 编辑与成品

使用宿主已有的图片编辑/生图能力，将底图作为实际图像输入，并把色卡只作为颜色参考。若只能文字生图、不能把底图传入编辑工具，说明限制，交付编辑提示词；不假装修改了原图。执行时明确：编辑目标、允许改变的颜色/光影/氛围、必须保留的主体与构图、是否允许新增元素，以及所选三色的作用。

用户只要求改色时，以保留内容为默认，不添加人物、物件、文字或标志。用户要重新构想场景时才扩展创作。手机型号或比例已提供则遵循；未给时默认竖版 9:16，重要主体不被裁掉，上方保持较安静的区域。需要扩展背景以适配比例时说明，不拉伸主体。不要承诺具体设备像素适配或逐像素保真。

生成后核对主体、构图、重要细节、配色倾向和竖版比例；交付实际图片，简短说明编号和需要注意的编辑偏差。图片生成不可用时如实说明。HEX 是生成意图，不能声称输出像素与三色完全一致；若用户必须完全保留原图像素，应另用确定性的调色流程，不能把生成式编辑说成精确替换。

底图和生成结果属于本次聊天；用户未要求保存到其他地方时，不上传到 GitHub、插件资产、公共链接或第三方存储。不把手机照片写回配色目录，不把照片当作扩充配色库的授权。插件只携带通用说明、原有 HEX 数据和干净色卡。

## 可直接使用的句子

```text
用 Mood Palette 给这张照片推荐 5 组配色，先让我选。
选第 2 组，用刚才的照片做手机壁纸，保留人物和构图，不加文字。
用 rain-slate-06 给这张照片改色，保持景物和拍摄角度，竖版 9:16。
保持底图内容，给我明亮、低饱和的粉红色方案，先不要出图。
```
