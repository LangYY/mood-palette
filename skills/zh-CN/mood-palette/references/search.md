# 日常颜色检索

不要求用户记主题名。先从用户语言提取基本颜色、明暗、饱和度和数量；用确定性检索获取候选，再按用途解释和展示。主题名和编号仍可直接查询。

## 语言与脚本

| 用户的表达 | 搜索条件 |
|---|---|
| 蓝色为主、蓝色系 | `--search 蓝色` |
| 黄色、粉红色、绿色、青色、紫色、棕色、黑白灰 | 对应基本颜色，例如 `--search 粉红色`；黑、白、灰分别查 |
| 浅一点、明亮、高明度 | `--lightness light` |
| 深一点、暗一些、低明度 | `--lightness dark` |
| 低饱和、柔和、不鲜艳 | `--saturation muted` |
| 鲜艳、高饱和、浓烈 | `--saturation vivid` |
| 没有限定颜色，只要明亮低饱和 | `--search any --lightness light --saturation muted` |
| 推荐 5 组 | `--limit 5`；未指定数量也默认 5 |

用户不用输入参数。由模型将自然语言映射到脚本支持的条件，不把完整自然语言句子直接当 `--search` 的颜色名。矛盾条件先指出；未覆盖的精细要求可读取候选的三色和特征继续筛选，清楚说明依据，不宣称脚本理解所有中文形容词。

```bash
python3 scripts/palette.py --search 蓝色 --limit 5
python3 scripts/palette.py --search 粉红色 --lightness light --saturation muted --limit 5
python3 scripts/palette.py --search any --lightness dark --saturation vivid --limit 5
```

## 搜索与展示的约定

- 结果只取库中完整色组，原始 HEX、编号与取值性质保持不变。
- 根据 RGB 得到日常色名，兼顾蓝灰、粉白等浅色与近中性色。色名是检索标签，可按用户理解进一步调整，并非标准色票名称。
- 检索按匹配颜色数量和色彩强度排序，优先覆盖不同主题，再补同主题中有明显差异的组。用不计顺序的近似颜色距离剔除换序和压缩造成的细微差别。
- 明暗筛选使用 HSL 明度、饱和度筛选使用 HSV 饱和度；要求整组均值与建议主色都符合条件。这些是便于检索的粗分指标，不是感知均匀测量，也不替代文字对比度。
- `suggested_primary` 是建议主色，`matching_colors` 是匹配用户颜色的色块；`color_details` 提供三色的普通名称与特征。原始记录没有主辅色与面积标签。
- `image` 是相对于 Skill 目录的干净三栏色卡路径；查编号与检索都会返回它。
- 返回 `status=ok`、`fewer_matches` 或 `no_matches`，以 `returned` 为准。结果不足时展示实际数量并说明；可建议放宽一个条件，未得到用户选择前不悄悄取消条件。

展示格式：序号 → 对应的干净三栏色卡 → 普通三色描述 → 建议主色与简短区别。直接读取每条记录的 `image` 相对路径，在支持图片的聊天里嵌入色卡（本地图片解析成绝对路径）；不能内嵌时提供图片文件。编号和可复制的原始 HEX 作补充，不能用名字或编号代替图片。命名和编号放次要位置。用户说“供我选择”时到此结束；用户选“第 2 组”后，将该序号映射为上一轮的实际编号再应用。

## 继续使用

```text
我想要一组以蓝色为主题的配色，推荐 5 个组合供我选择。
给我看看粉红色、明亮、低饱和的组合。
选第 3 组，用它生成一张阅读 App 首页示意图。
继续用这一组，把我当前页面的颜色换掉，布局别动。
```

选色阶段直接展示库内预渲染的三栏色卡，不重新生成色卡。用户只要色值时返回文本；要求插画、海报或 UI 等应用效果图时，再进入生图流程。

## 没有 Python 的宿主

读取 [免运行索引](portable-search.json)，按 `基本色|明暗或any|饱和度或any` 查找条件（例如 `blue|any|any`）。每项包含真实 ID 与建议主色，已按现有算法排序、去重；取前 N 组后，从 `palettes.json` 获取原三色和色卡路径。没有匹配就报告实际数量。更新色值或检索算法后运行 `python3 scripts/build_portable_search.py` 重建，并运行测试核对全部 117 个条件。
